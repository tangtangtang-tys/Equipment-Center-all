# 设备中心平台与经销商模块培训产品文档

## 文档说明

本文用于企业内部跨部门成员熟悉设备中心平台及经销商相关模块，支持 30–45 分钟产品宣讲和重点功能演示。

- **培训基准**：当前实际线上版本
- **线上入口**：[设备中心平台](https://operations.eye4.cn/micro-op/#/77)
- **适用对象**：客服/售后、运维/技术支持、运营/产品、经销商管理人员、超管/平台管理员
- **演示重点**：设备查询与设备详情、经销商 APP 测试账号、平台操作日志
- **截图策略**：文字流程为主，关键页面预留截图位置
- **状态说明**：当前可用、当前可演示、规划中
- **登录范围**：从登录完成后的页面开始，不介绍账号申请、权限开通和角色配置

> 培训时应优先以线上页面和当前业务规则为准。本地原型、演示数据和历史需求文档只用于补充理解，不替代线上实际结果。

## 一、产品概览

### 1.1 产品定位

设备中心平台是面向设备运营、客服、运维和技术支持的统一管理入口，用于集中查看设备身份、激活、绑定、运行状态、增值服务、日志和生命周期信息。

经销商相关模块是设备中心面向渠道协作的业务管理入口，围绕经销商组织维护 APP 测试账号、设备测试记录、账号操作日志及自动唤醒等组织级配置。

两部分共同形成业务闭环：

“设备事实查询 → 经销商组织协作 → APP 测试验证 → 操作记录追溯 → 问题反馈闭环”

### 1.2 目标用户与主要关注点

| 角色 | 主要关注 | 常用模块 |
| --- | --- | --- |
| 客服/售后 | 设备是否存在、是否激活、是否绑定、服务是否有效 | 设备查询、设备详情、绑定用户、增值服务 |
| 运维/技术支持 | 在线状态、网络、心跳、日志、物联网卡、异常证据 | 设备状态、日志记录、物联网卡、设备详情 |
| 运营/产品 | 经销商范围、业务规则、测试数据和版本变化 | 经销商列表、自动唤醒、平台日志、版本说明 |
| 经销商管理人员 | 经销商信息、APP 测试账号、测试记录、账号维护 | 经销商列表、APP 测试账号、设备测试记录 |
| 超管/平台管理员 | 高风险操作、权限边界、平台审计 | 设备管理、禁用/恢复、平台操作日志 |

### 1.3 核心价值

1. **集中查询**：减少在设备、用户、订单、日志等多个系统之间重复查找。
2. **事实判断**：在单设备详情中确认设备身份、归属、状态和服务信息。
3. **测试隔离**：经销商使用 APP 测试账号进行抽检和复测，避免测试行为混入正式用户流程。
4. **过程可追溯**：创建账号、重置密码等后台操作形成可查询的操作记录。
5. **协作有依据**：客服、技术支持、运维和产品可以基于同一页面信息沟通。

### 1.4 主要应用场景

- 用户反馈设备无法使用，需要确认设备状态和绑定关系。
- 技术支持判断设备离线、4G 不上线、P2P/网络异常等问题。
- 经销商收货后使用测试账号进行抽检和异常复测。
- 跟单或经销商管理人员创建、查询或重置 APP 测试账号。
- 核对账号创建、密码重置等操作由谁在什么时间完成。
- 运营或产品查看组织级自动唤醒配置和修改历史。

### 1.5 产品与设备差异

- IPC、NVR、车载、BK、4G 低功耗设备的身份、网络、电量、存储和日志字段存在差异。
- 4G 设备重点关注物联网卡、ICCID/IMEI、信号和低功耗状态。
- 非 4G 设备对物联网卡相关字段通常显示“不适用”。
- 经销商停用后仍可查看详情，但通常不能创建新的 APP 测试账号。
- 不同角色看到的敏感字段、日志详情和高风险操作入口可能不同。

### 2.3 APP 测试账号边界

APP 测试账号用于经销商设备抽检、样机验证和异常复测。测试账号不作为真实消费者账号使用，不用于兑换正式云存权益；测试结束后，经销商测试人员应在 APP 端解绑设备。具体账号能力以当前线上页面和业务规则为准。

## 三、业务流程

### 3.1 标准使用流程

1. 进入线上设备中心并完成登录。
2. 根据工作目标选择“设备中心”或“经销商列表”。
3. 通过设备 ID、经销商名称/ID或组织层级定位对象。
4. 查看详情、状态、服务、测试记录或日志。
5. 在授权范围内执行创建账号、重置密码、禁用/恢复等操作。
6. 根据页面结果判断是否需要转交其他部门。
7. 使用平台操作日志或相关记录完成结果核对。
8. 按反馈规范提交问题和证据，形成闭环。

### 3.2 设备问题排查流程

1. 客服获取设备 ID并查询。
2. 判断设备是否存在、激活、绑定用户。
3. 查看设备可用状态，确认是否被禁用或受其他限制。
4. 查看最近心跳、网络/P2P、存储和物联网卡信息。
5. 查看登录、报警、重置等相关日志。
6. 设备或网络异常转技术支持/运维；归属、服务或规则问题转客服运营/产品。
7. 反馈中附上设备 ID、时间、页面现象和关键日志。

### 3.3 经销商测试账号流程

“确认经销商 → 创建 APP 测试账号 → 安全交付临时密码 → 经销商在 APP 中测试 → 查看设备测试记录 → 测试结束后解绑 → 必要时重置密码 → 操作日志留痕”

### 3.4 典型业务案例

**设备离线或无法预览**

- 客服确认设备 ID和用户信息。
- 技术支持查看在线状态、最后心跳、P2P/MQTT和日志。
- 运维核查服务链路、节点或数据同步。
- 产品判断是否属于版本、规则或已知问题。

**经销商需要抽检设备**

- 管理人员查询并选择经销商。
- 创建 APP 测试账号并查看临时密码。
- 经销商测试人员使用账号添加设备并完成抽检。
- 管理人员核对设备测试记录，测试完成后由经销商在 APP 端解绑设备。

**追溯后台操作**

- 按日期查询平台操作日志。
- 核对操作类型、对象、操作人、时间和结果。
- 将日志作为跨部门沟通和问题反馈依据。

### 3.5 系统和部门协作

| 协作对象 | 设备中心提供 | 对方提供或确认 |
| --- | --- | --- |
| 用户中心 | 绑定用户入口和归属信息 | 用户账号状态和绑定关系 |
| 订单/权益系统 | 设备增值服务展示入口 | 服务订单、权益和有效期 |
| 日志/消息平台 | 登录、报警、运行证据 | 原始日志和实时消息 |
| 运维/技术支持 | 设备状态和问题线索 | 服务链路、接口和设备侧判断 |
| 经销商/跟单 | 测试账号、测试记录、操作日志 | 测试目标、组织信息和测试结果 |
| 产品/运营 | 规则、版本和业务口径 | 需求确认、版本说明和问题定级 |

## 四、实际操作

### 4.1 基础操作

1. 打开线上入口：[设备中心平台](https://operations.eye4.cn/micro-op/#/77)。
2. 登录完成后，根据菜单进入设备中心或经销商列表。
3. 确认当前页面、组织范围和设备/经销商对象。
4. 执行查询、查看详情或新增操作。
5. 确认页面提示、列表结果和日志记录。

### 4.2 演示一：设备查询与设备详情

**演示目标**：在一个详情页内完成设备身份、归属、状态和服务的基础判断。

1. 进入设备查询入口。
2. 输入设备 ID并执行查询。
3. 打开目标设备详情。
4. 阅读顶部摘要：设备 ID、型号、激活状态、在线状态和可用状态。
5. 查看基础信息：SN、UUID、IMEI/ICCID、MAC、固件和生产信息。
6. 查看用户、设备状态、增值服务、日志记录和物联网卡。
7. 根据事实判断是否转交客服、技术支持、运维或产品。

### 4.3 演示二：经销商 APP 测试账号

**演示目标**：创建可追溯的 APP 测试账号，并查询设备测试记录和账号操作记录。

1. 进入“设备中心 > 经销商列表”。
2. 使用经销商名称或经销商 ID检索目标经销商。
3. 查看经销商详情，确认名称、ID、层级和设备数量。
4. 打开“APP 测试账号”Tab，点击“创建账号”。
5. 确认经销商组织、账号名称、客户端和大区等信息。
6. 提交后查看创建结果和临时密码，并按安全要求交付。
7. 必要时重置密码；打开“设备测试记录”核对测试行为。
8. 测试结束后确认经销商在 APP 端解绑设备。

### 4.4 演示三：平台操作日志

1. 在经销商详情中打开“操作日志”，或进入独立的平台操作日志入口。
2. 选择操作日期或时间范围。
3. 查看日志时间线或列表。
4. 核对操作人、对象、动作、所属经销商和结果。
5. 对照业务反馈确认是否成功、重复或需要重试。
6. 将日志信息复制到问题单或跨部门沟通记录中。

### 4.5 自动唤醒配置说明

- 配置范围是当前经销商组织，不自动覆盖其他组织。
- 设备首次绑定时读取所属组织当时有效的默认值。
- 已绑定设备及其用户现有配置不因组织默认值修改而自动迁移。
- 配置保存后应查看当前值和历史记录。
- 变更是否写入平台操作日志，以线上当前版本页面和业务规则为准。

## 五、问题处理

### 5.1 常见问题分类

| 问题类型 | 典型现象 | 首要处理方式 |
| --- | --- | --- |
| 数据问题 | 查不到设备、经销商或测试记录 | 确认 ID、组织范围、查询条件和同步状态 |
| 权限问题 | 看不到模块或操作按钮 | 确认当前账号角色和数据范围，转平台管理员 |
| 操作问题 | 创建失败、重置失败、保存无响应 | 记录提示、时间和步骤，重试一次后反馈 |
| 接口/系统问题 | 报错、加载失败、字段异常 | 截图并记录发生时间，转运维/技术支持 |
| 设备状态问题 | 离线、无法预览、4G 不上线 | 结合状态、日志、物联网卡和版本信息判断 |
| 业务规则问题 | 测试行为、禁用影响或服务口径不一致 | 转运营/产品确认规则和边界 |

### 5.2 问题反馈必填信息

- 设备 ID或经销商名称/ID；
- 用户、测试账号或相关组织信息；
- 问题发生时间；
- 所在页面和具体操作；
- 页面提示或错误信息；
- 已执行的操作和重试结果；
- 关键页面截图；
- 相关日志时间、操作人和对象。

### 5.3 客服技术支持和反馈渠道

反馈渠道按公司当前工单或内部协作渠道执行，培训时将实际入口补充到本节。提交问题时由客服/售后先收集事实和诉求；技术支持根据状态、日志和网络信息判断技术线索；运维核查接口、消息、服务节点和数据同步；运营/产品确认业务规则、版本口径和优先级；平台管理员/超管处理权限和高风险操作。问题闭环后，由发起人补充处理结果和验证结论。

### 5.4 版本更新说明

本次培训不展开具体版本差异：

- 以线上页面显示的当前版本和功能为准。
- 关注产品公告、变更说明或内部发布通知。
- 版本更新后重点核对菜单入口、字段、按钮和日志记录。
- 发现行为变化时，反馈版本/环境、页面、操作步骤、实际结果和期望结果。
- 规划中能力不得作为当前版本承诺对外说明。

培训结束后，参训人员应能回答：

1. 设备中心和经销商模块分别解决什么问题？

3. 如何为经销商创建 APP 测试账号并查看测试记录？
4. 如何通过平台操作日志确认账号操作过程？
5. 遇到问题时应收集哪些信息、转交哪个部门？
6. 如何区分当前可用、当前可演示和规划中能力？
